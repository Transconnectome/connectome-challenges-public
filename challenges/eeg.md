# EEG · 뇌파에서 눈 깜빡임 흔적 찾아보기

![EEG 챌린지 · 눈 깜빡임 찾기 — 뇌파의 큰 파형은 뇌일까, 눈일까? 흐름: 합성 뇌파 생성, 큰 파형 찾기, 눈에서 왔나, 정답과 비교. 선택 단계로 실제 공개 뇌파로 확인. 그림의 시간은 합성 과제 기준이다.](../assets/challenge_eeg.png)

*그림 오른쪽 위의 시간은 합성 데이터 과제 기준입니다. 실제 공개 데이터 단계(선택)는 약 1시간이 더 걸립니다.*

- 난이도: **L1** (안내를 따라 실행하고, 본 것을 설명하는 과제)
- 데이터: **연습용 합성 뇌파**(실제 사람의 기록이 아니며, 눈 깜빡임이 언제 들어갔는지 정답 파일이 함께 만들어짐). 선택 단계에서 **실제 공개 뇌파**(PhysioNet EEGBCI, 6명 약 8 MB, 정답 없음)를 씁니다.
- 필요한 것: 노트북 컴퓨터(GPU 없어도 됨), Python 3.11 또는 3.12, 인터넷(패키지 설치와 공개 데이터 다운로드용)
- 예상 시간: 설치와 첫 실행 30분 안팎, 합성 과제 2–3시간 + 실제 데이터(선택) 약 1시간 (추정)

## 무엇을 해 보나요?

EEG(뇌파)는 머리 표면 여러 위치에서 잰 전압입니다. 이 전압에는 뇌 활동만 있는 것이 아니라 눈 깜빡임이나 근육 움직임도 섞여 들어갑니다. 이런 섞여 든 신호를 **아티팩트**라고 부릅니다. 이 과제에서는 뇌파를 그려 보고, 크게 솟는 파형이 어디서 왔는지 근거를 들어 설명합니다.

## 시작하기

처음이라면 [시작 안내](../START_HERE.md)의 설치 단계를 먼저 따라 해 주세요. 설치가 끝났다면 저장소 맨 위 폴더에서 아래를 실행합니다(이미 `challenges/eeg` 폴더에 있다면 `cd` 줄은 건너뜁니다). 시작 안내 ④를 이미 마쳤다면 이 블록은 건너뛰고 과제로 갑니다.

```bash
cd challenges/eeg
python generate_synthetic_eeg.py
jupyter notebook eeg_synthetic_example.ipynb
```

`data/eeg_raw.fif`(19채널, 250 Hz, 3분)와 `data/ground_truth.json`(정답)이 몇 초 안에 만들어집니다. 정답 파일은 분석을 마친 뒤에 여세요. 파일 구성과 데이터를 만드는 방법은 [합성 데이터 안내](eeg/README.md)에 있습니다.

## 과제

1. 예제 노트북을 위에서부터 실행하며 시간(초)과 전압(µV, 마이크로볼트 = 100만분의 1볼트)의 단위를 확인합니다.
2. 신호를 그리고 큰 변화가 보이는 구간 세 곳을 표시합니다. 노트북의 `plot_channels(시작초, 길이, marks=[시점1, 시점2])`를 쓰면 표시한 시점에 빨간 세로선이 그려집니다.
3. 그 파형이 뇌에서 왔는지, 눈에서 왔는지 판단할 근거를 적습니다. 채널 위치, 모양, 부호를 보세요.
4. 눈 깜빡임과 눈의 좌우 움직임을 구분하고, 찾은 깜빡임을 `ground_truth.json`과 비교합니다. 몇 개를 맞혔고 몇 개를 놓쳤는지, 놓친 이유가 무엇인지 적습니다.
5. 새 데이터로 다시 해 봅니다(노트북 마지막 칸의 "다른 데이터로 반복"). 아래 명령으로 다른 seed의 데이터를 만들고, 노트북에서 `"data/`로 시작하는 경로 두 곳을 `"data_seed7/`로 바꿔 같은 분석을 반복합니다.

```bash
cd challenges/eeg   # 이미 이 폴더라면 건너뜁니다
python generate_synthetic_eeg.py --seed 7 --out data_seed7
```

- 기준값(`threshold`)을 50이나 120으로 바꿔 봅니다. 기본 데이터에서 50이면 38회 중 37회, 120이면 28회를 찾고, 틀린 것은 둘 다 0개입니다. 50으로 낮춰도 50.9 µV짜리 깜빡임 하나를 놓치는데, 찾기 전에 신호를 부드럽게 하는 필터(저역 통과)가 정점을 조금 낮추기 때문입니다. 기준을 낮춰도 틀린 것이 생기지 않는 이유(합성 데이터의 배경 뇌파가 깜빡임보다 훨씬 작다)와, 실제 기록이라면 무엇이 달라질지 설명할 수 있으면 과제를 이해한 것입니다.

## 실제 공개 데이터로 확인하기

합성 데이터에서 연습한 방법을 실제 사람의 기록에 적용합니다. 이미 `challenges/eeg` 폴더에 있다면 아래의 `cd` 줄은 건너뜁니다. 데이터는 PhysioNet에 공개된 **EEG Motor Movement/Imagery Dataset**(EEGBCI)입니다. 109명이 64채널로 기록했고, 1초에 160번 측정했습니다. 이 중 **run 1**(눈을 뜨고 가만히 있는 1분 기록)만 씁니다. 실제 기록에는 정답 파일이 없습니다.

```bash
cd challenges/eeg
python generate_synthetic_eeg.py      # 비교용 합성 데이터. 이미 만들었다면 건너뜁니다.
jupyter notebook eeg_real_data.ipynb
```

노트북 설정 칸(첫 코드 칸)의 `SUBJECTS`에 적힌 사람(기본 1–6번)의 run 1 파일을 노트북 옆 `data_real/` 폴더에 받습니다. 다른 곳에 받으려면 `DATA_DIR` 한 줄만 바꿉니다. 채널 이름 정리(`Fp1.` → `Fp1`), 64채널 중 10-20 배치 19채널 고르기, 볼트(V)를 µV로 바꾸기는 노트북이 대신 합니다.

- **받는 양과 시간**: 6명에 7.7 MB입니다. 2026-10-09에 두 번 받았을 때 두 번 모두 5분 30초 안팎(332–338초) 걸렸습니다. 서버에서 오는 속도가 1초에 20 KB 남짓이었기 때문이며, 네트워크에 따라 달라집니다. 한 번 받은 뒤에는 노트북 전체가 몇 초(실측 3.4초) 안에 실행됩니다.

### 할 일

1. 노트북을 위에서부터 실행해 합성 예제와 같은 방법(Fp1·Fp2 평균, 10 Hz 저역 통과, 80 µV 기준으로 정점 찾기, 두피 분포)을 적용합니다.
2. 사람별로 기준을 넘은 정점의 수(분당)와 정점 크기를 합성 데이터와 비교합니다(노트북 7단계). 사람끼리 얼마나 다른지도 봅니다. 기준을 넘은 정점이 모두 깜빡임이라는 보장은 없습니다.
3. 실제 기록에서만 생기는 어려움을 반 쪽 이내로 설명합니다. 노트북 4단계 그림에서 깜빡임이 아닌 것 같은 정점을 둘 이상 골라 이유를 적고, 기준값 하나를 모든 사람에게 쓰기 어려운 이유를 5단계 표와 4단계 출력의 '배경 크기'를 근거로 적습니다.

### 이용 조건과 인용

2026-10-09에 데이터 페이지(https://physionet.org/content/eegmmidb/1.0.0/)에서 확인한 내용입니다.

- 라이선스: **Open Data Commons Attribution License v1.0** (https://physionet.org/content/eegmmidb/view-license/1.0.0/). 페이지 원문: "Anyone can access the files, as long as they conform to the terms of the specified license." 출처를 밝히면 쓸 수 있는 라이선스입니다.
- 결과를 공유할 때 페이지가 요구하는 인용(원문 그대로):
  - 데이터: Schalk, G. (2009). EEG Motor Movement/Imagery Dataset (version 1.0.0). PhysioNet. RRID:SCR_007345. https://doi.org/10.13026/C28G6P
  - 원 논문: Schalk, G., McFarland, D.J., Hinterberger, T., Birbaumer, N., Wolpaw, J.R. BCI2000: A General-Purpose Brain-Computer Interface (BCI) System. IEEE Transactions on Biomedical Engineering 51(6):1034-1043, 2004.
  - PhysioNet 표준 인용: Pollard, T., Moody, B. E., Lehman, L., Gow, B., Fernandes, C., Xie, C., Johnson, A., Mark, R. G., & Heldt, T. (2026). PhysioNet as a global platform for biomedical research. Nature Health. https://doi.org/10.1038/s44360-026-00096-z
- 받은 데이터 파일은 이 저장소나 결과물에 올리지 마세요. 필요한 사람은 노트북으로 직접 받습니다.

- 기본 설정(1–6번, 80 µV)에서 6명 합계 정점 112개, 6.1분, 분당 18.4개가 나옵니다. 사람별 분당 정점 수는 S001 17.7, S002 19.7, S003 22.6, S004 6.9, S005 15.7, S006 27.5개입니다.
- 정점 크기(중앙값)는 사람에 따라 121–391 µV이고, 사람별 값의 중앙값은 176 µV입니다. 같은 함수로 구한 합성 데이터(seed 42)는 분당 12.0개, 154 µV입니다.
- 배경 크기는 실제 기록에서 사람에 따라 12–74 µV(중앙값 22 µV), 합성 데이터에서 7 µV입니다.
- 두피 분포(6명 평균)는 Fp1 +217, Fz +40, Cz −40, Pz −71, O1 −87 µV입니다. 이마에서 가장 크고 뒤로 가며 부호가 바뀌는 모양은 합성 데이터와 같습니다. 다만 정점을 이마 채널(Fp1·Fp2)에서 골랐고 19채널 평균을 기준으로 삼았기 때문에, 이 모양의 일부는 고르는 방식만으로도 생깁니다. 눈 전용 전극(EOG) 없이 이것만으로 깜빡임이라고 확정할 수는 없습니다.
- 기준값을 50 µV로 내리면 S001은 18개에서 34개로 늘어납니다. 200 µV로 올리면 S004와 S005는 0개가 됩니다. 기준값에 따라 개수가 바뀌는 것은 합성 데이터도 같습니다. 실제 데이터에서 기준 하나가 어려운 진짜 이유는 사람마다 배경 크기(12–74 µV)가 달라, 같은 80 µV가 어떤 사람에게는 배경의 1배 남짓이고 어떤 사람에게는 6배가 넘기 때문입니다.
- 4단계 그림에서 S001의 26–30초 근처 정점과 S005의 0초 정점을 살펴보세요. 왜 깜빡임이 아닐 수 있는지 설명할 수 있으면 과제를 이해한 것입니다.
- 위 숫자는 Linux aarch64, Python 3.12, MNE 1.13.2에서 확인했습니다. 같은 숫자가 나오면 설치와 다운로드가 제대로 된 것입니다.

## 선택 심화

다른 채널과 비교해 같은 시점에 변화가 있는지 확인합니다. 뒤통수 쪽 채널(O1, O2)에서는 깜빡임이 어떻게 보이나요? `plot_channels(0, 20, channels=["Fp1", "O1", "O2"], marks=detected)`처럼 채널을 골라 그릴 수 있습니다.

## 합성 데이터의 한계

합성 뇌파는 깜빡임, 알파파, 채널 간 상관 같은 몇 가지 특성만 실제와 비슷하게 맞춘 것입니다. 이 데이터에서 잘 되는 방법이 실제 기록에서도 그대로 잘 된다고 가정하지 마세요. 자세한 한계는 [합성 데이터 안내](eeg/README.md#한계)에 있습니다.

## 용어

- **채널**: 머리 표면의 측정 위치 하나. 이름 앞 글자가 위치를 뜻합니다(Fp=이마, F=앞쪽, C=가운데, T=옆머리, P=정수리 뒤, O=뒤통수).
- **Hz(헤르츠)**: 1초에 몇 번인지. 250 Hz는 1초에 250번 측정했다는 뜻입니다.
- **정점**: 파형에서 가장 높이 솟은 지점.
- **두피 분포**: 같은 순간의 신호 크기를 머리 위치별로 그린 지도. 신호가 어디서 왔는지 짐작하는 근거가 됩니다.
